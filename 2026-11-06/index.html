Blender's user interface, as a library you can use from Python, Rust, JavaScript (React, Svelte), C, C++ and Dear ImGui.

People spent decades building and optimizing Blender's GUI. It's battery and memory efficient, and super duper fast. We decoupled it, to give everyone a chance to build their own products with it. It supports multiple languages and frameworks, so you won't miss a beat!

BUI takes the user interface of Blender (its widget drawing, its interaction rules and its look) and turns it into a standalone UI library with a small C core. Your code builds the widget tree and handles callbacks. Layout, input, drawing and presenting all happen in fast native code, on the CPU or the GPU.

At the heart of BUI is the kit: a small runtime written in C. The kit holds every widget in one tree, lays them out, handles the mouse and keyboard, and draws them the way Blender does. The drawing code is a C port of Blender's own widget code, and the interaction follows Blender's rules. On top of the kit sit bindings: thin layers that let Python, Rust, JavaScript, C++ and Dear ImGui talk to it.

What BUI is not:

  • Not Blender. It contains the parts of Blender's UI code it needs and builds on its own. You don't need Blender installed, and you don't need to know Blender to use it.
  • Not a browser. The Rust and JavaScript sides use HTML and CSS as a UI language, but there's no browser engine, no webview and no network.
  • Not a re-imagining. The widget drawing is ported from Blender's 
    interface_widgets.cc

Blender's interface is famous for how it feels. You press a number field and drag: the cursor vanishes, the value glides under your hand, and you never hit the edge of the screen. You type 

2*pi

That interface is also fast and frugal. It redraws only what changed, sleeps when nothing does, and starts in milliseconds. BUI exists so that any app, in any language, can have both: Blender's feel, and Blender's efficiency.

  • You have a tkinter app and wish it looked less like 1998. Run it on BUI, unchanged.
  • You're building a tool for artists who already know Blender. Give them the panels, sliders and shortcuts their hands expect.
  • You write Rust or React and want a native desktop UI without shipping a browser.
  • You use Dear ImGui and want it to look and feel like Blender, with one build flag.
  • You're curious how a UI toolkit works. The source is readable, and the concepts are explained in plain words.

#include <stdio.h>
#include "BUI_kit.h"

static void on_event(void *data, BKNode *node, int kind, void *ref, double a, double b)
{
  if (kind == BK_EV_CLICK) printf("clicked %s\n", BK_get_str(node, "text"));
  else if (kind == BK_EV_CHANGE) printf("%s = %g\n", BK_get_str(node, "label"), BK_get_num(node, "value"));
}

int main(void)
{
  BKNode *root = BK_node_new("frame");          /* everything is a node */
  BK_set_num(root, "padding", 8);               /* configured by property name */

  BKNode *size = BK_node_new("slider");
  BK_set_str(size, "label", "Size");
  BK_set_num(size, "max", 10);
  BK_set_num(size, "value", 2.5);
  BK_node_add(root, size, -1);
  BK_geom_set_manager(size, BK_GEOM_PACK);      /* Tk's packer, in C */
  BK_geom_set(size, "fill", 1);

  BKNode *apply = BK_node_new("button");
  BK_set_str(apply, "text", "Apply");
  BK_node_add(root, apply, -1);
  BK_geom_set_manager(apply, BK_GEOM_PACK);

  BKContext *ctx = BK_context_new(root);        /* input, focus, popups, undo */
  BKHost host = {0};
  host.emit = on_event;                         /* the window fills in the rest */
  BK_context_set_host(ctx, &host);

  if (BK_window_supported()) {                  /* Win32, X11 or Cocoa */
    BKWindow *win = BK_window_new(ctx, "BUI from C", 320, 120);
    BK_window_show(win);
    BK_window_run();
    BK_window_free(win);
  }
  BK_context_free(ctx);
  BK_node_free(root);
  return 0;
}

BUI has two renderers, and they draw the same pixels.

  • The software raster (
    gpu/intern/gpu_raster.c
    ) is the default. It draws anti-aliased shapes with signed-distance coverage, like Blender's widget shaders, into one frame buffer, compares it with the last frame in 64×32 tiles, and reports only the tiles that changed. Big canvases draw in parallel bands on Windows (
    BUI_RASTER_THREADS
    ). It needs nothing from your graphics card and uses the least memory.
  • The GPU renderer is opt-in: Direct3D 11 on Windows (
    gpu/intern/gpu_d3d11.c
    ) and OpenGL 3.3 core on Linux (
    gpu/intern/gpu_gl.c
    ). It's modeled on Blender's instanced widget drawing: each primitive is one 128-byte instance of a single uber-shader, so a frame is a few instanced draw calls. Text and images are cached in atlases. Frames render into a persistent target, so only damaged regions redraw; on Windows, a flip-model swap chain presents dirty rectangles. On Linux, 
    libGL
    , 
    libEGL
    and 
    libX11
    are loaded at run time (GLX for windows, EGL for offscreen), so no GL headers are needed, and BUI falls back to the CPU where OpenGL is missing.

The shaders evaluate the software raster's formulas: the parity test finds 10 of 172,800 pixels that differ by more than 3/255, on both backends.

More: Rendering.

Leave a BUI window open and walk away: it uses no CPU at all. Hover a button, and BUI redraws that button, not the window.

  • A change marks only its widget's rectangle as dirty (popups get a margin for their shadow).
  • Dirty rectangles merge (up to 24 per window).
  • If nothing is dirty, the loop doesn't render; it sleeps until the next input or timer.
  • Only the dirty regions are redrawn, clipped to their rectangles.
  • The raster compares the new pixels with the last frame in 64×32 tiles; a redraw that changed nothing reports nothing.
  • Only damaged tiles reach the screen (Win32 copies them, X11 sends each rectangle with 
    XPutImage
    , Cocoa invalidates them, the GPU presents dirty rectangles).

On the full component demo, that's about 0.7 ms for a complete frame and about 0.05 ms for a hover or number-scrub frame. Animations run only while something moves, paced to the display. More: Damage rendering.

Do I need Blender installed?

No. BUI contains the parts of Blender's UI code it needs and builds on its own.

Is it really my unchanged tkinter app?

Yes. 
blenderui-tk app.py
makes 
import tkinter
return BUI's implementation, which covers every public tkinter and ttk name. Nine real programs are tested to behave identically on the standard library and on BUI. See

the limitationsfor the few differences.

Is it a web browser in Rust?

No. There's no browser engine and no network. BUI takes HTML elements and CSS as a

UI language: they are laid out with

taffyand drawn by BUI's engine, with Blender's widgets where you ask for them, in a native window. JavaScript is optional: the Rust crate needs none, and the JavaScript packages drive the same engine.

Is the Dear ImGui support a re-implementation?

No. It's the real Dear ImGui (vendored, MIT), running on a BUI backend, so every function behaves as upstream. The optional Blender-widgets build swaps only how ImGui's widgets are drawn and how they react to the mouse, by compiling an edited copy of 
imgui_widgets.cpp
.

How is it different from Electron, Electrobun or GPUIX?

  • Electron ships Chromium with every app: on the order of 100 MB or more.
  • Electrobun runs on Bun and renders in the system's webview. It's small to download, but the UI is still a browser page.
  • GPUIX, like BUI, renders React natively: React drives Zed's GPUI.

BUI also renders natively, with Blender's widgets, a much larger part of CSS, Tailwind, and hooks backed by signals.

bui build
makes a 5 MB executable that reaches its first frame in about 70 ms.

Do the macros cost performance?

rsx!
, 
#[component]
, 
css!
and 
tw!
expand at compile time into the same builder calls you would write by hand. Tailwind classes are compiled to CSS once, on first use. Hooks are a few nanoseconds per read or write.

Can I change the colors?

Yes. Switch between Blender's Dark and Light themes at run time (

Themes), color individual widgets in every API, and use full CSS on plain HTML elements in Rust and JavaScript. Loading any other Blender theme file is coming soon.

Does it run on my Mac?

Probably, but nobody has checked yet: the Cocoa host is written and experimental. Python can always fall back to the Tk window (
BUI_HOST=tk
). If you try it, the notes in
